# Audit finding evidence ledger

Baseline: `ab6657cd7b14fa484181605cddcb4575e8a88558`. Wire formats and checkpoint
encodings were held constant. “Green” below means the focused regression and its relevant control
pass in the final tree.

Two labels record what happened after this audit, and each row keeps its original resolution for the
record. **Superseded** means the tree changed later and the row no longer describes it. **Reopened**
means a finding recorded as disproven was later shown to be real.

| Finding | Initial evidence | Resolution | Final evidence |
| --- | --- | --- | --- |
| Queue terminal attempt zero | `0` passed validation and could never be reached by a positive delivery count. | Reproduced and fixed. | `ShouldRejectZeroTerminalAttemptBeforeReadingTheDelivery`; durable-attempt positive control remains green. |
| Fitz positive terminal threshold | Fitz reports `AttemptUnavailable`; validation previously occurred only after reserve. | Reproduced and fixed. | Hosted startup rejects before connection; generic durable transports retain the threshold behavior. |
| Queue missing terminal handler | A direct or generic hosted runner could begin transport enumeration with no disposition policy; validation was limited to Fitz pre-connection checks. | Reproduced and fixed. | Every queue runner validates and disposes a preflight scope before enumeration, successful-only queues still require a handler, each delivery uses and validates a fresh scope, and generic/Fitz restart boundaries propagate configuration failure. |
| Lazy queue envelope rereads | A malformed envelope escaped through repeated lazy property reads and remained reserved. | Reproduced and fixed. | Invocation is cached through callback, acknowledgment, and telemetry; malformed envelopes complete once as `DeserializationFailure`; invalid-transport and callback-before-ack controls pass. |
| Queue read ownership classification | Unknown contracts were completed as malformed and retryable reads ignored the durable threshold. | Reproduced and fixed. | Permanent reads always reach the terminal handler; retryable reads abandon below threshold and reach `RetryLimitReached` at threshold; later deliveries continue after successful terminal disposition. |
| Request envelope classification fallthrough | Missing members and malformed JSON could escape without permanent classification, while an unsupported version was not rejected until v2 fields had been parsed. | Reproduced and fixed. | Missing, null, wrong-kind, and fractional versions remain permanent; every unsupported integer version is retryable before any version-specific field is inspected; valid v2 classifications remain intact. |
| Abandoned queue failure visibility | Lazy read failures abandoned for redelivery emitted a delivery outcome but no runner-fault diagnostic. | Reproduced and fixed. | Every abandoned read failure records exactly one queue execution fault; terminal-handled poison payloads do not duplicate it. |
| Notification burst overflow | Fitz subscriptions are pull-based async enumerables and the queue retains only one pending `MoveNextAsync`. No callback channel or unbounded fan-out reproduced. | Disproven; no production change. **Reopened (2026-09-24):** a related overflow exists. `FitzRequestQueueConsumer` and `PortiaWorkloadService` advance the Fitz subscription only when idle, so a busy consumer leaves wake-ups undrained; after 256 the subscription ends with `SubscriptionBackpressureException`. The workload service records the fault and resubscribes; the queue read loop ends. **Fixed (2026-09-24):** the queue consumer and the event store's notifier drain every buffered wake-up before each re-read, and an overflow that still happens counts as one wake-up and resubscribes instead of faulting. The notice and schedule consumers are unchanged: their notifications carry the request and are read continuously. | `BusyConsumerDrainsWakeUpsSoTheSubscriptionNeverOverflows`, `WakeUpOverflowResubscribesAndReservesInsteadOfFaulting`, `ShouldDrainBufferedCommitsSoABusyWorkloadNeverOverflows`, `ShouldTreatAnOverflowedSubscriptionAsAWakeUpAndResubscribe`; existing queue/notice/schedule continuation and poison-message suites pass. |
| Hosted workload identity drift | Hosted binding discarded the explicit registration name, reverting to constructor defaults used by Portia 0.1. | Reproduced and fixed. | Hosted registration names remain the stable ownership, checkpoint, and effect identities; constructor names remain manual-run defaults. |
| Unnamed Fitz coordination | Request-only workers and custom-coordinator workloads were rejected even though they do not use Fitz fleet membership. | Reproduced and fixed. | Only Fitz-coordinated workloads require `ApplicationName`/`UseFleet`; custom-coordinator workloads, request-only workers, and client-only setup remain valid unnamed. |
| Scheduled system-principal assertion | Version-1 envelope subject/issuer were trusted directly and a validator could be captured outside its registered lifetime. | Reproduced and fixed. | Hosted consumers resolve and dispose a distinct scoped `IScheduledRequestActorValidator` for each firing; the public constructor still requires an explicit validator. |
| Scheduled validator transient loss | Thrown and transient-result validation failures dropped a firing with no acknowledgment/redelivery path; the first repair retried forever at a fixed interval. | Reproduced and fixed. | The same firing receives at most three attempts with one- and two-second injected-clock delays and a fresh disposed scope per attempt. Each transient result or throw records a validation fault; cancellation propagates, rejection/exhaustion loses the current firing once, malformed envelopes never enter validation, and the route continues. |
| Stale reactor checkpoint | Unconditional Fitz KV save could overwrite a newer checkpoint. | Reproduced and fixed. | Reactor runner uses an internal expected-checkpoint save; legacy public stores and legacy checkpoint decoding remain unchanged. |
| MCP authorization bypass | Endpoint conventions already own HTTP authorization and `RequireAuthorization` returns 401 before tool dispatch. | Disproven; no production change. | Authenticated tool and endpoint authorization controls pass. |
| Authenticated async credential loss | Cookie/custom-authenticated HTTP principals could enqueue with a null credential and later execute anonymously. | Reproduced and fixed. | Such calls return 400 before enqueue; Bearer and explicitly authorized anonymous paths remain supported. |
| JWT role parity | No same-token HTTP/worker difference reproduced under equal validation parameters. | Disproven; no production change. **Reopened (2026-09-24), fixed in PR #80:** a difference does exist with ASP.NET Core's default bearer options. `JwtBearerOptions.MapInboundClaims` defaults to true, while `JwtRequestActorValidator` kept the token's own claim names (`sub`, `unique_name`, `role`), so on a worker `Identity.Name`, `ClaimTypes.NameIdentifier`, and `IsInRole` did not resolve for the same token. The validator now maps by default and accepts `mapInboundClaims: false`. | `ShouldMapInboundClaimsLikeJwtBearerByDefault` and `ShouldKeepTokenClaimNamesWhenInboundMappingIsOff`. |
| Culture-sensitive HTTP binding | Generated supported scalar parsing already supplies `InvariantCulture`; semantic `TryParse` discovery covers provider signatures. | Disproven; no production change. | Generated binding culture tests pass. |
| Nullable OpenAPI null default | A null default was emitted as a schema default even though optionality already carries the contract. | Reproduced and fixed. | Null defaults are omitted; non-null defaults and optional parameters remain described. |
| Recursive MCP root reference | Nested references were rewritten, but a bare `"$ref":"#"` was not. | Reproduced and fixed. | Both bare-root and nested references now remain within the result envelope. |
| PORTIA suppression retention | Ordinary generator locations scanned their syntax tree and retained serialized suppression state, invalidating otherwise equal portable models after pragma edits. | Reproduced and fixed. | `DiagnosticLocation` contains location data only; pragma and `SuppressMessage` evaluation occurs only for actual `PORTIA020`, `PORTIA024`, and `PORTIA029` candidates. Valid transport inputs remain cached. Registration and HTTP interceptor outputs still refresh their required Roslyn source checksums. |
| Invalid transport IDs | Blank IDs disappeared from discovery and invalid IDs could fault only when generated declarations ran. | Reproduced and fixed. | `PORTIA029` covers blank and syntactically invalid IDs; valid custom transport controls pass. |
| Transport incremental equality | Transport arrays used reference equality while diagnostic locations were omitted from equality. | Reproduced and fixed. | `RequestTransportComponent` uses structural transport-list equality and includes locations, so declaration movement relocates duplicate diagnostics while unrelated inputs remain cacheable. |
| Modifier-free partial code fix | Leading declaration trivia stayed on the declaration after inserting its first modifier. | Reproduced and fixed. | The inserted `partial` token owns leading trivia; existing modifier and Fix All controls pass. |
| Locking-store conformance hang | The conformance test opened the stale write batch before committing the winner, which deadlocks a locking store. | Reproduced and fixed. | Winner commits first while the stale batch retains its original expected checkpoint. |
| Publish privilege and ordering | One write-scoped job built, tested, packed, pushed packages, then pushed its tag. | Reproduced and fixed. **Superseded (2026-09-16, PR #39; `contents: write` added in 30419f4):** the split was removed. `publish.yml` is again one `workflow_dispatch` job on `main` with `contents: write` and `packages: write`; it packs (which builds), pushes with `--skip-duplicate`, then tags. It runs no tests and no locked-mode restore; those run in `ci.yml`. | The read-scoped prepare job and exact-SHA tag-parity check no longer exist. |

Final local gates at the time of the audit: format verification, Release build, public API baseline,
all broker-free tests, locked package/NativeAOT consumer execution, isolated Fitz broker integration,
`actionlint`, and `git diff --check`. The public API baseline script (`eng/verify-public-api-baseline.sh`)
was removed in PR #39 and not replaced. `Microsoft.CodeAnalysis.PublicApiAnalyzers`, wired since PR #21 with
warnings as errors, still requires every public API change to be declared in `PublicAPI.*.txt`, but nothing
now requires `PublicAPI.Unshipped.txt` to be empty before publishing.
